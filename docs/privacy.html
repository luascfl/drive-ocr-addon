Privacy policy: OCR for Drive

Last updated: 2026-10-16. Back to the home page.

Who we are

OCR for Drive is a Google Drive add-on that creates a searchable copy of scanned PDFs using optical character recognition (OCR). It is a project maintained by an individual and is in a testing phase. Contact: open an issue in the project's GitHub repository.

What we do with your data

When you ask for OCR on a PDF, the add-on sends our server the file's identifier and the authorization you gave the add-on. The server downloads that PDF from your Drive, runs OCR and saves a new file, "<name> (OCR).pdf", in the same folder as the original. The add-on only accesses the files you grant, one at a time (the drive.file permission). It also reads the name, type and identifier of the items you select in Drive so it can show the right button, and it uses the "connect to an external service" permission to talk to our server.

What we store

  • The content of your documents is not stored. The PDF and the page images stay in a temporary directory on the server only while the job runs, and are deleted when it finishes, including on error. The deletion is a plain delete, not a secure overwrite of the disk.
  • Your authorization (access token) is not stored. It exists only in the server's memory during the job and is discarded afterwards.
  • To enforce a per-person usage limit, the server keeps, in memory only, an unreadable code derived from your Drive identity. It disappears when the server restarts. We do not read or store your e-mail address.
  • The add-on itself keeps, in your own Apps Script user properties (private to you), the identifiers and file names of your last 10 OCR jobs, so the status screen can show them. It never stores document content.
  • Server technical logs contain only: file size, page count, OCR language, timings, the outcome (success or error code) and date and time. They contain no file name, identifier, e-mail address, document text or IP address. Today these logs are limited only by the server's disk space, with no expiry set.
  • The state of each job (running, finished, error) is kept in memory only and expires after 1 hour.

Who we share it with

Only Google, to access your Drive and validate your authorization, and Oracle Cloud, which hosts the server in the Sao Paulo, Brazil region. We do not sell data, do not use it for advertising and do not use it to train models.

Usage limit

To protect the service, each user can run at most 2 jobs at the same time and 30 per day.

Your rights and how to revoke access

You can revoke access at any time at myaccount.google.com/permissions. Because we do not store the content of your documents or data that identifies you, there is no data of yours on our side to export or delete. The "(OCR).pdf" files created stay in your Drive and only you control them. For questions, open an issue in the repository.

Use of Google API data

The use and transfer to any other app of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.
